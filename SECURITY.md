# Security Policy

## Supported Versions

Security support begins with the first implemented release. Until then, this repository contains planning and structure artifacts only.

## Reporting a Vulnerability

Do not open a public issue for a suspected vulnerability. Contact the project maintainers privately with a concise description, affected location, reproduction details, impact, and any suggested mitigation.

Please do not include secrets, private user data, or exploit payloads beyond what is necessary for safe reproduction. Maintainers will acknowledge reports, assess severity, coordinate remediation, and disclose fixes responsibly.

## Security Expectations

- Do not commit credentials, tokens, keys, or production data.
- Use environment-managed secrets only.
- Report dependency, authentication, authorization, validation, data exposure, and deployment concerns promptly.
- Follow the architecture and database security requirements in `docs/`.
